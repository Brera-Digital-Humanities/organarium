# Repertory of the Ancient Organ

[🇮🇹 Italiano](README.md) · **🇬🇧 English**

WordPress child theme of **Twenty Twenty-Five** for cataloguing and presenting the musical repertory of the ancient organ. The theme integrates five custom Gutenberg blocks: four interactive ones based on the **WordPress Interactivity API** (`featured-zoom`, `timeline`, `post-list`, `mappa-interattiva` — the last one also integrates **Leaflet.js** for cartographic visualization) and one dynamic server-side block (`acf-field`) for displaying ACF fields in single post templates.

## Build

**Prerequisite:** the project requires Node.js 24. Activate the correct version with nvm before any other command:

```bash
nvm use 24
```

Install dependencies and build:

```bash
npm install
npm run build      # production build
npm run start      # watch mode for development
```

The `--experimental-modules` flag enables ES6 modules; `--blocks-manifest` automatically generates `build/blocks-manifest.php`.

The `webpack.config.js` file extends the default `@wordpress/scripts` configuration to add a dedicated entry for the global stylesheet (`src/style/style.scss` → `build/style/style-style.css`) alongside the block entries. With `--experimental-modules` the default config is an array (scripts + modules): the global entry is added to the "scripts" config.

> Files in the `build/` folder are the compilation output and must not be edited by hand: sources are in `src/`. **`build/` is not committed to the repository**: after `git clone` it is mandatory to run `npm install && npm run build` before activating the theme, otherwise `register_block_type()` will not find the compiled blocks and WordPress will display an error.

## Tests

Unit test suite based on `wp-scripts test-unit-js` (Jest + jsdom, already included in devDependencies, no extra configuration).

**Execution:**

```bash
nvm use 24
npm run test:unit
```

**Architecture**

Each interactive block isolates filtering, sorting and computation logic in a `logic.js` file next to `view.js`. The `logic.js` file exports pure functions: it does not import `@wordpress/interactivity`, Leaflet, nor touch the DOM. The view imports and uses these functions; tests exercise them in isolation. Functions actually shared between multiple blocks live in `src/shared/filters-logic.js` and are re-exported by each `logic.js`, so the views still import a single local module.

**Existing suites**

| Suite | File tested | What it covers |
|---|---|---|
| `src/shared/__tests__/filters-logic.test.js`            | `src/shared/filters-logic.js`         | Shared logic: `matchesPeriodo`, `postMatchesFilters` (with optional `periodo`), `isValueAvailable` (with optional `extraMatch` for additional constraints such as the century range), `filterAndSortPosts` (with optional `extraFilter`) |
| `src/mappa-interattiva/__tests__/logic.test.js`         | `src/mappa-interattiva/logic.js`      | `escapeHtml`, `clusterIconSize`, `groupPostsByCoord`, `buildMarkerFilters`, `markerMatchesFilters`, `filterPostsForPanel`, `makeCard` |
| `src/timeline/__tests__/logic.test.js`                  | `src/timeline/logic.js`               | Century-range wrapper (`filterAndSortPosts`, `isValueAvailable`), `isPillInvisible`, `markerPercent`, `formatCenturyLabel`, `scrubberJumpIndex` |
| `src/post-list/__tests__/logic.test.js`                 | `src/post-list/logic.js`              | `postMatchesFilters`, `filterAndSortPosts`, `isValueAvailable`, `cardOrder`, `isCardVisible`, `countFilteredPosts` |

**Adding tests to an existing block**

The datasets used in existing tests follow a common schema (array of posts with `id`, `categoria`, `materiale[]`, `tecnica[]`, `sort_key`, `data_per_timeline`); reusing it reduces friction. To test new behaviour:

1. Add the pure function to the block's `logic.js` (or to `src/shared/filters-logic.js` if the logic is shared with other blocks).
2. Import it in `view.js` instead of the inline version.
3. Add the case to the corresponding `__tests__/logic.test.js` file.

**Adding tests to a new block**

```
src/<new-block>/
├── view.js                      # imports from ./logic
├── logic.js                     # pure functions
└── __tests__/
    └── logic.test.js
```

`wp-scripts test-unit-js` automatically detects `*.test.js` files under `src/`, no path configuration required. Functions shared with other blocks belong in `src/shared/` with their own `__tests__/`.

## Global stylesheet

The child theme's general styles are written in **SCSS** and compiled by `wp-scripts` alongside the blocks.

**Structure:**

```
src/style/
├── style.scss          # Entry point (imports partials with @use)
├── _variables.scss     # Aliases of TT5 CSS custom properties
├── _typography.scss
├── _layout.scss
├── _main-navbar.scss   # Overrides for the parent theme's main navbar
└── _blocks.scss        # Core block overrides and global selectors
```

- The `src/style/style.scss` entry is compiled to `build/style/style-style.css` (the `mini-css-extract-plugin` convention used by wp-scripts produces `<entry>-style.css`).
- The root `style.css` file remains **only** as the child theme header (required by WordPress to recognize the theme). All rules have been migrated to SCSS partials.
- `functions.php` enqueues the compiled stylesheet as a dependent of `twentytwentyfive-style`, so child rules cascade after parent rules without unnecessary `!important`. The version is derived from `filemtime()` for automatic cache busting.

**Compatibility with Twenty Twenty-Five:**

TT5 is a block theme: the source of truth for the design system is `theme.json`, which exposes presets as CSS custom properties (`--wp--preset--color--*`, `--wp--preset--font-family--*`, `--wp--preset--spacing--*`). To stay compatible, `_variables.scss` **does not redefine** values but aliases them:

```scss
$color-accent-1: var(--wp--preset--color--accent-1);
$color-contrast: var(--wp--preset--color--contrast);
$font-baloo:     var(--wp--preset--font-family--baloo-2);
```

This way changes to the palette or typography in `theme.json` (or via the Site Editor) automatically propagate to the SCSS without requiring recompilation. Styles specific to core blocks should preferably go in `theme.json` → `styles.blocks.*`; SCSS is reserved for complex selectors, hover/transitions and rules the Site Editor does not cover.

> Custom block styles (`src/<block>/style.scss`) remain separate: wp-scripts compiles them via their `block.json`.

## Multilingual

The site is multilingual via **Polylang** (free version). The theme is internationalized with the text-domain `jerus-organo`; translation files live in `languages/` in the format `jerus-organo-{locale}.{po,mo}`. Configured languages: Italian (slug `it`, default) and English (slug `en`, locale `en_GB`). PHP helpers check `function_exists('pll_*')` before calling Polylang functions: disabling the plugin makes the code degrade transparently (`__()` returns the original, helpers return the input unchanged), which is useful during local development without Polylang installed.

**Strings covered**

- UI of the 4 interactive blocks: filter labels, buttons, status messages
- Choices of the ACF fields (`categorie_generali`, `materiale`, `tecniche`) in the filter pills and card tags. The values (slugs) remain language-agnostic so as not to break saved filters or cross-language user preferences
- Preset labels of the `acf-field` block when they exactly match the IT defaults — custom labels are left intact
- ACF field labels in the admin via the `acf/load_field` filter

**PHP helpers** (in `functions.php`):

| Function | What it does |
|---|---|
| `jerus_load_textdomain()` | Reloads the `.mo` for the current locale; hooked to `init`/`wp`/`admin_init`/`rest_api_init` to cover the different moments at which the language gets resolved |
| `jerus_localize_term_ids()` | Maps a `term_id` (or array) to the equivalent in the current language |
| `jerus_query_with_lang_fallback()` | Runs `WP_Query` with fallback to the default language if the current one is empty; re-maps `tax_query` term IDs because Polylang/i18n keeps them separate per language |
| `jerus_acf_choices_translations()` / `jerus_get_translated_choices()` | Maps `field_name` → `[value => translated label]` for radio/checkbox fields. Used by the 3 blocks instead of `get_field_object()` to avoid depending on the ACF cache |
| `jerus_resolve_acf_field_block_label()` | Translates the saved label of the `acf-field` block if it matches the IT preset; otherwise leaves it as is |
| `jerus_remap_tax_query_terms()` | Recursively re-maps the term IDs of a `tax_query` (including nested ones) to a specific language |

**Per-language header/footer (FSE)**

The `render_block_data` filter rewrites the slug of `core/template-part` by adding the current-language suffix (e.g. `header` → `header-en`) when the language is not the default. The variant can be a file `parts/header-en.html` in the child theme or a `wp_template_part` post saved from the Site Editor; if it doesn't exist, the original slug is used. To extend beyond `header`/`footer`, edit the `$swappable` array in the filter.

**Content fallback**

When the current language has no posts:
- **Archive/category/tag/home** pages: a `the_posts` filter on the main query returns posts from the default language
- The 3 blocks (**timeline**, **post-list**, **mappa-interattiva**): their `WP_Query` go through `jerus_query_with_lang_fallback()`

In all cases UI labels stay in the current language: the fallback acts only on post contents.

**Adding/updating a locale**

```bash
msgfmt languages/jerus-organo-{locale}.po -o languages/jerus-organo-{locale}.mo
```

The `.mo` files must be committed (they are what WordPress reads at runtime).

**Maintaining the `acf-field` block labels**

The label presets are **duplicated by design** between `src/acf-field/index.js` (the `FIELDS` array) and `functions.php` (`jerus_acf_field_block_labels()`). The two sources must be identical character by character: the PHP render only translates if the saved label exactly matches the IT preset (`===`). Adding or renaming a field requires updating both maps plus the `msgid` entries in the `.pot`/`.po`.

## ACF data model

The theme depends on a single field group **DETTAGLIO SCHEDA** assigned to the `post` type. Position `normal`, labels above, `show_in_rest: 0`, no required fields, no conditional logic. This section documents the group structure so that it can be rebuilt manually from ACF → Field Groups.

**Fields of the group:**

| Name (machine) | ACF type | Label | Use |
|---|---|---|---|
| `data`                          | text         | DATA VISUALIZZATA            | Human-readable date shown in cards and detail pages (e.g. "ca. 1450", "XII sec."). Decoupled from `data_per_la_timeline` to allow descriptive strings |
| `ubicazione`                    | text         | UBICAZIONE                   | Current location of preservation; displayed in list, map and popup cards |
| `autore`                        | text         | AUTORE                       | Free-text attribution. Shown only on the detail page |
| `tecnica_e_materiali`           | text         | TECNICA E MATERIALI          | Extended textual description (discursive version, distinct from the controlled choices `materiale` / `tecniche`) |
| `dimensioni`                    | text         | DIMENSIONI                   | Free-text measurements |
| `provenienza`                   | wysiwyg      | PROVENIENZA                  | History of previous locations, rich text with full toolbar |
| `trattato_completo`             | wysiwyg      | TRATTATO COMPLETO            | Discursive treatment of the work, rich text |
| `edizione`                      | text         | EDIZIONE                     | Short bibliographic reference |
| `fonti`                         | wysiwyg      | FONTI                        | Bibliography / links, rich text. Displayed with a top border as a separator |
| `data_per_la_timeline`          | number       | DATA NUMERICA PER LA TIMELINE| **Year as integer**; negative values for BC (e.g. `-200`). Sort key for timeline and post-list, and dot-positioning key in the century bar |
| `posizione_per_mappa`           | open_street_map (ACF Extended) | POSIZIONE PER MAPPA | Map marker coordinates. `return_format: "leaflet"`, `zoom: 12`, initial layer `OpenStreetMap.Mapnik`. Read in PHP with `get_post_meta()` to get the raw data (see mappa-interattiva block) |
| `didascalia_foto_in_primo_piano`| wysiwyg      | DIDASCALIA FOTO IN PRIMO PIANO | Caption of the featured image, displayed by the `featured-zoom` block |
| `categorie_generali`            | radio        | CATEGORIE PER GENERALI       | Typological category (single-choice). Filter in the timeline / post-list / mappa-interattiva blocks. See table below |
| `materiale`                     | checkbox     | MATERIALI                    | Prevailing materials (multi-choice). Multiple-value filter. See table below |
| `tecniche`                      | radio        | TECNICHE                     | Execution technique (single-choice, `allow_null: 1`). Filter. See table below |

### Controlled choices

The three choice fields use `return_format: "value"`, so PHP receives the key (left column). Labels are resolved at runtime with `get_field_object()` and — for `categorie_generali`, whose label contains a parenthesized description — truncated at the first `(` by a PHP helper.

**`categorie_generali`** (radio, single-choice, vertical layout):

| Value | Label |
|---|---|
| `pittura`     | Pittura su Supporto Mobile *(mobile works or part of the organ's furnishing: oil, tempera, canvas, panel — altarpieces, organ shutters)* |
| `monumentale` | Decorazione Murale e Architettonica *(integral part of a building: fresco, stucco, plaster — organ in its spatial context, music-making angels)* |
| `plastica`    | Arti Plastiche e Scultoree *(terracotta, including glazed, marble, stone, bronze — three-dimensional objects)* |
| `grafica`     | Grafica e Disegno su Carta *(engraving, sanguine, pencil, mixed technique — study drawings and diffusion prints)* |
| `vitree`      | Arti Applicate e Decorative *(glass, mosaic, inlay — more stylized renderings due to material constraints)* |

**`materiale`** (checkbox, multi-choice, vertical layout):

`tela`, `legno`, `intonaco`, `calce`, `pietra`, `terracotta`, `marmo`, `bronzo`, `carta`, `tessuto`, `vetro`, `piombo` — label = capitalization of the value.

**`tecniche`** (radio, single-choice, `allow_null: 1`):

`affresco`, `stucco`, `mosaico`, `scultura`, `modellato`, `bassorilievo`, `incisione`, `disegno`, `vetrata`, `miniatura`, `arazzo`, `pittura`, `intarsio` — label = capitalization of the value.

### Implementation notes

- **`data_per_la_timeline`** must be an integer. The timeline builds 17 century segments in the range `[-200, 1600)` and positions dots proportionally to the value; values outside the range are ignored. The post-list sorts via PHP `usort` on this field (more reliable than `WP_Query` on numeric meta without a registered key).
- **`posizione_per_mappa`** requires **ACF Extended**: the `open_street_map` type is not in ACF core. `return_format: "leaflet"` makes `get_field()` return the widget HTML instead of the raw data, so the mappa-interattiva block reads the field with `get_post_meta()` to access `lat`/`lng`.
- **WYSIWYG vs text**: `provenienza`, `trattato_completo`, `fonti`, `didascalia_foto_in_primo_piano` allow HTML; the `acf-field` block renders them with `wp_kses_post`. Other text fields are passed to the same function, which is safe also on plain text.
- **`show_in_rest: 0`** on the group: fields are not exposed via the REST API. If in the future block-editor editing with native bindings were needed, this should be set to `1` on every relevant field with `allow_in_bindings` enabled.

### 2. Timeline 3D (`ttf-child/timeline`)

Presents the posts in **two visualization modes** selectable by the user: a 3D carousel with perspective effect and a CSS grid. Supports a per-century navigation bar, multiple ACF-based filters and date sorting. User preferences (century, filters, sort, view, active card) are persisted in a session cookie.

**Features:**

*Century Bar*
- Chronological navigation bar covering the range 200 BC – 1600 AD in **17 segments**: each segment has a minimum width of **110 px desktop / 90 px mobile** (`flex: 1 0 110/90px`) and grows equally if there is remaining space, never below the minimum. Empty segments are `disabled` and rendered with reduced opacity, but keep the same width as the others
- Segments do not wrap (`flex-wrap: nowrap`): the bar overflows the container with `width: calc(100vw - 40px)` + `margin-left: calc(20px - 50vw + 50%)` — 20 px of gutter from the viewport edges, also chosen to avoid the page horizontal scrollbar Chrome generates with `100vw` when the vertical scrollbar is present. When segments exceed the viewport, the bar is **horizontally draggable**: mouse via pointer events with `cursor: grab` → `grabbing`; the synthetic click on the segment is suppressed if the user has dragged (capture + `stopPropagation`). Touch: `touch-action: pan-x pan-y` lets the browser handle the pan. Scrollbar visually hidden
- The scroll position (`scrollLeft`) is persisted in the `tl_prefs` cookie as `centuryScrollLeft` (250 ms debounce on `scroll`) and restored on reload in `requestAnimationFrame` after layout. **The bar never moves automatically**: only user action changes the position
- Each segment corresponds to a century; the first covers 200 BC – 0 with label `200 a.C.`, the second covers 0 – 100 AD with label `0`, the others follow up to the 1500 – 1600 segment. The first segment has no opening vertical tick
- Each segment displays: century label, vertical tick, continuous horizontal line and **square dots** (5×5 px desktop / 4×4 px mobile) positioned proportionally to the post's `sort_key` within the range; dots are vertically stacked in **5-year** buckets (e.g. 0-4, 5-9, 10-14)
- The active segment is colored with `accent-4`; the dot of the post highlighted in the carousel becomes `contrast` (black)
- Clicking a segment: loads posts of that century, resets all filters and closes the filter panel

*Timeline view*
- 3D carousel with CSS perspective (`perspective: 500vw`) and up to 5 cards visible simultaneously (active, prev/next, prev2/next2)
- Navigation via arrow buttons, keyboard (←/→), **mouse wheel** on the viewport or scrubber, and **horizontal touch swipe** on the viewport (mobile): the viewport has `touch-action: pan-y`, so vertical page scroll stays native while the horizontal axis is recognized as carousel navigation (50 px threshold, predominantly horizontal direction)
- Arrow buttons auto-hide when visible posts (after filters) are ≤ 1 (nothing to navigate)
- **Click on a non-active card**: brings it to the foreground (hit-test via `getBoundingClientRect` on non-active cards, because the 3D context `preserve-3d` does not reliably delegate pointer events to children)
- Draggable scrubber timeline (desktop) with a marker for each post and label with the year; can be hidden from the Site Editor and auto-hides when visible posts (after filters) are fewer than 3

*Grid view*
- Responsive CSS Grid (`auto-fill`, columns with 360 px min)
- Dynamic card order based on the index computed client-side

*Filters*
- Collapsible filter panel with selectable pills for:
  - **Category** (ACF field `categorie_generali`)
  - **Material** (ACF field `materiale`)
  - **Technique** (ACF field `tecniche`)
- Filters act on the posts of the **selected century** in the century bar
- Pills have three states:
  - **active** — selected
  - **disabled** (opacity 0.35) — the value exists in at least one post of the active century but is excluded by the current combination of the other filters
  - **invisible** (`display: none`) — the value does not appear in any post of the active century; reappears automatically when the century changes
- Active filters badge with per-filter or global removal
- Visible posts counter indicator

*Sorting*
- Ascending/descending toggle with FLIP animation based on `sort_key` (ACF field `data_per_la_timeline`)

*Preferences persistence (session cookie)*
- `tl_prefs` cookie (session, no `max-age`) written in JS via `callbacks.savePrefs` (`data-wp-watch`, reactive)
- Saved fields: `centuryMin`, `centuryMax`, `viewMode`, `sortAsc`, `activeIndex`, `categoria`, `materiali`, `tecniche`, `centuryScrollLeft`
- PHP reads the cookie at render and initializes the context with the saved preferences; `viewMode` is validated against the block's `allowedViews`

**Block attributes (configurable from the Site Editor):**

| Attribute | Values | Description |
|---|---|---|
| `postSource` | `all` / `current_category` / `fixed_category` | Source of posts to display |
| `selectedCategory` | Category ID | Fixed category (if `fixed_category`) |
| `allowedViews` | `both` / `timeline` / `grid` | Views available to the user |
| `showScrubber` | `true` / `false` | Show or hide the timeline scrubber (visible only if `allowedViews ≠ grid`) |

**Interactivity API — store `timeline-3d`:**

| Element | Description |
|---|---|
| state `visiblePosts` | Posts filtered by active century + ACF filters, sorted |
| state `isViewTimeline/isViewGrid` | Active view mode |
| state `filtersOpen` | Filter panel openness |
| state `isCenturyActive` | Active century-bar segment (local ctx: `segMin`) |
| state `isDotActive` | Active dot — post matches the highlighted card (local ctx: `postIndex`) |
| state `cardOffset/isActive/isPrev/isNext...` | Card position in the carousel |
| state `markerLeft/scrubberThumbLeft` | Scrubber positioning |
| state `showScrubber` | Scrubber visible only if filtered posts are ≥ 3 |
| state `isPillActive` | Selected pill (local ctx: `filterGroup`, `filterVal`) |
| state `isPillDisabled` | Greyed-out pill: the value exists in the century but is excluded by other filters |
| state `isPillInvisible` | Hidden pill: the value does not appear in any post of the active century |
| state `isPillUnavailable` | Union of disabled + invisible — used for the HTML `disabled` binding of the button |
| action `setCentury` | Changes the active century, resets filters and closes the panel |
| action `toggleFilters/clearFilters/togglePill` | Filter management |
| action `setViewTimeline/setViewGrid` | View switching |
| action `toggleSort` | Sort reversal with FLIP |
| action `next/prev` | Carousel navigation |
| action `scrubberPointerDown/Move` | Scrubber drag |
| action `goToMarker` | Direct navigation from a marker |
| callback `init` | Setup of plain DOM listeners (keyboard, wheel, click on non-active cards); inline replica of `visiblePosts` using the captured `ctx` to avoid re-evaluating the store's computed values from outside the Interactivity API reactive context |
| callback `savePrefs` | Session cookie writing (reactive via `data-wp-watch--save`) |
| callback `lazyLoadImages` | Per-century thumbnail lazy-loading (reactive via `data-wp-watch--lazy`): `<img>` elements are rendered with `data-src` instead of `src`; when `activeCenturyMin/Max` or filters change, the callback selects `.timeline-card:not(.is-hidden) .card-thumb img[data-src]` (and the grid analogue), adds `is-loading` to the wrapper, sets `src = dataset.src` and removes `data-src` only on `load`/`error`. CSS: `img[data-src] { opacity: 0 }` with `transition` on opacity → fade-in upon attribute release, no alt/broken-image icon during loading |

### 3. Post List (`ttf-child/post-list`)

Presents the posts in a **vertical list with horizontal layout** (thumbnail on the left at 33%, text on the right) with ACF filters identical to those of the timeline, a **sort toggle** (ascending/descending) and **infinite scroll**: posts are revealed 10 at a time on sentinel detection via `IntersectionObserver`. Posts are ordered by the ACF field `data_per_la_timeline` (PHP `usort` for the initial order; client-side the sort is recomputed reactively in `state.filteredPosts` together with active filters, so sorting always respects the current selection).

**Features:**

- Horizontal cards: image 33% / aspect-ratio 4:3 + text body (date, location, title, excerpt, category tag)
- **Data** and **Ubicazione** fields grouped into a single meta block with a bold label, one below the other
- Filtered-results counter visible in the top bar
- **Sort** ascending/descending by `data_per_la_timeline`: the toggle acts on the filtered posts (sort is applied after filters in `state.filteredPosts`); the visual order is realized via CSS `order` on the cards (the DOM remains in the initial PHP order), so reordering is purely reactive with no re-render. Changing sort resets `visibleCount` to 10
- **Collapsible filters** with selectable pills for **Category**, **Material** and **Technique** — same logic as the timeline: single toggle per group, pills disabled for unavailable combinations, active filters badge with per-filter or global removal; every filter change resets `visibleCount` to 10
- **Infinite scroll**: an invisible sentinel (1 px) placed after the list is observed by `IntersectionObserver` with `rootMargin: 300px`; on detection it increments `visibleCount` by 10 until there are no more posts to show. If the sentinel remains intersected after the increment (e.g. few posts or tall viewport, cases in which the observer would not refire because it only notifies state changes), `loadMore()` reschedules itself in `requestAnimationFrame` until it leaves the viewport or there are no more posts
- **Thumbnail lazy-load with fade-in**: `<img>` elements are rendered with `data-src` instead of `src`, so no browser request happens at the initial render. When `visibleCount` or filters change, the `lazyLoadImages` callback selects cards that are no longer hidden, applies `is-loading` to the wrapper (CSS spinner) and sets `src` only then; `data-src` is removed on `load`/`error` and the CSS (`img[data-src] { opacity: 0 }` + `transition`) produces the fade-in
- Status messages: "End of results" (all filtered posts visible) and "No results found" (filters with no matches)
- Ability to **hide the entire filters UI** from the editor: when disabled, the bar only shows the counter

**Block attributes (configurable from the Site Editor):**

| Attribute | Values | Description |
|---|---|---|
| `postSource` | `all` / `current_category` / `fixed_categories` | Source of posts to display |
| `selectedCategories` | Array of category IDs | Fixed categories (if `fixed_categories`) — multiple selection via checkboxes |
| `showFilters` | `true` / `false` | Show or hide the entire filter UI on the frontend |
| `imageRatio` | `4/3` / `3/4` | Thumbnail proportions in the cards (horizontal or vertical) |

**ACF fields used:**

| Field | Type | Use |
|---|---|---|
| `data` | Text | Shown in the card's meta-line with the label "Data" |
| `ubicazione` | Text | Shown in the card's meta-line with the label "Ubicazione" |
| `categorie_generali` | Select | Category filter and card tag |
| `materiale` | Multiple select | Material filter |
| `tecniche` | Multiple select | Technique filter |

**Interactivity API — store `post-list`:**

| Element | Description |
|---|---|
| state `filteredPosts` | Posts filtered by the three ACF groups and sorted by `sort_key` according to `sortAsc` |
| state `filteredCount` | Number of filtered posts (shown in the counter) |
| state `isVisible` | Card visibility: passes the filters AND its index in `filteredPosts` is < `visibleCount` (local context: `postIndex`) |
| state `cardOrder` | Card's CSS `order` in the flex column based on its position in `filteredPosts` (local context: `postIndex`) |
| state `sortLabel` | Sort-button label (`Ordina ↑↓` / `Ordina ↓↑`) |
| state `hasMore` | There are filtered posts beyond `visibleCount` |
| state `showEndMessage/showEmptyMessage` | Status messages for end-of-list or no results |
| state `filtersOpen/filterToggleLabel` | Filter panel openness and toggle button label |
| state `hasActiveFilters` | At least one filter active |
| state `isPillActive/isPillDisabled` | Active state and conditional availability of pills |
| state `hasCategoriaFilter/Materiali/Tecniche` | Presence of filter per group |
| state `activeCategoriaLabel/Materiali/Tecniche` | ACF label of the active filter |
| action `toggleFilters/clearFilters/togglePill` | Panel and filter management (every change resets `visibleCount = 10`) |
| action `clearCategoria/clearMateriali/clearTecniche` | Single-filter removal |
| action `toggleSort` | Inverts `sortAsc` — `state.filteredPosts` is reactively reordered and each card updates `data-wp-style--order`; resets `visibleCount = 10` |
| callback `init` | Sets up `IntersectionObserver` on the sentinel — captures `ctx` during the directive to access Preact signals from inside the asynchronous callback. Recursive `loadMore()` (in `requestAnimationFrame`) to handle the "sentinel still intersected after the increment" case |
| callback `lazyLoadImages` | Thumbnail lazy-load (reactive via `data-wp-watch--lazy`): on `visibleCount` increase, filter change or `sortAsc` toggle (needed because reordering can bring to the foreground posts never loaded before even if `visibleCount` doesn't change), selects `.pl-card:not(.pl-hidden) .pl-card-img img[data-src]`, applies `is-loading` to the wrapper and sets `src = dataset.src`; `data-src` removed on `load`/`error` to trigger the CSS fade-in |

**Architecture:**
- All posts are rendered server-side in PHP and passed into the context; JS controls how many are visible via `visibleCount`
- The Preact context is based on reactive signals: `ctx` captured in `callbacks.init` is readable/writable from the `IntersectionObserver` callback with no need for `getContext()`
- Filter visibility is handled entirely on the PHP side (`$show_filters`): when disabled, the filter markup is not emitted

### 4. Interactive Map (`ttf-child/mappa-interattiva`)

Displays a **Leaflet.js map** with geolocated pins for every article that has the ACF field `posizione_per_mappa` filled in. Pins open a popup with thumbnail, location and linked title. The tile-layer color filter is chosen by the editor in the Site Editor panel; the frontend user cannot change it.

**Features:**

- Circular SVG pins with fixed colors independent of the category. Sizes: **26×26 px** for a single post, **28×28 px** when the pin represents multiple co-located posts (in that case the central dot is replaced by the **post count**). The SVG viewBox stays at 28: the single-post pin is simply scaled at 93% to visually emphasize the count pins
- **Automatic clustering** (Leaflet.markercluster): nearby pins are grouped into an SVG cluster showing the **total number of contained posts** (sum of child markers' `_postCount`, not the marker count); it opens via spiderfication at high zoom or disbands into individual pins at `disableClusteringAtZoom: 14`. `maxClusterRadius: 30` (contained radius to avoid overly wide aggregations)
- **Coordinate grouping**: multiple articles with the same coordinates share a single marker (with a count on the pin); clicking opens a side panel with the cards of the articles matching the active period (or all of them if no period filter is active), separated by a horizontal divider
- Cards with thumbnail, `ubicazione` field and linked title (color `accent-3 #6b2a0b`)
- **Collapsible side filters panel** (36 px → 450 px, toggle with vertical text) with pills for **Category**, **Material**, **Technique** and **Period** — same logic as the timeline: pills disabled for unavailable combinations, ACF labels resolved via `get_field_object()`, active filters badge with per-filter or global removal
- Automatic viewport: `fitBounds` on the filtered markers or zoom on the single visible marker. **On mobile (≤767 px), at first render** the map does `fitBounds` on a fixed Europe box (`[[35, -10], [70, 40]]`, padding 16px) instead of the actual markers: this prevents the extreme zoom-out when the dataset includes intercontinental pins (e.g. Europe + Americas), which would render European pins indistinguishable on the small screen. From the second `updateMarkers` onwards (filter change, etc.) normal behavior resumes. The `firstRender` flag is kept in non-reactive `refs` (`WeakMap`) so as not to trigger `data-wp-watch`
- 4 CartoDB styles with CSS filter applied to the tile pane: `natural`, `warm`, `teal`, `dark`

**Available map styles:**

| Key | Name | Base tile | CSS filter |
|---|---|---|---|
| `natural` | Light natural | CartoDB light | sepia(25%) saturate(0.9) brightness(1.02) hue-rotate(5deg) |
| `warm` | Burnt warm | CartoDB light | sepia(45%) saturate(1.1) brightness(0.98) hue-rotate(-5deg) |
| `teal` | Cool teal | CartoDB light | sepia(10%) saturate(0.8) brightness(1.03) hue-rotate(140deg) |
| `dark` | Earthy dark | CartoDB dark | sepia(35%) saturate(0.7) brightness(0.85) hue-rotate(5deg) |

**Block attributes (configurable from the Site Editor):**

| Attribute | Values | Description |
|---|---|---|
| `postSource` | `all` / `current_category` / `fixed_category` | Source of posts to display |
| `selectedCategory` | Category ID | Fixed category (if `fixed_category`) |
| `mapHeight` | 300–900 px | Height of the map canvas |
| `mapStyle` | `natural` / `warm` / `teal` / `dark` | Chromatic style of the tile layer |

**Required ACF fields:**

| Field | Type | Use |
|---|---|---|
| `posizione_per_mappa` | Open Street Map (ACF Extended) | Marker coordinates — read with `get_post_meta()` to get the raw data instead of the widget HTML |
| `ubicazione` | Text | Shown in the popup in place of the date |
| `categorie_generali` | Select | Category filter |
| `materiale` | Multiple select | Material filter |
| `tecniche` | Multiple select | Technique filter |

**Interactivity API — store `mappa-interattiva`:**

| Element | Description |
|---|---|
| state `filtersOpen` | Side-panel open/closed state |
| state `filterToggleLabel` | Dynamic label of the toggle button (`Filtra ↓ / ↑`) |
| state `isPillActive/isPillDisabled` | Active state and conditional availability of pills |
| state `hasActiveFilters` | At least one filter active |
| state `hasCategoriaFilter/Materiali/Tecniche` | Presence of filter per group |
| state `activeCategoriaLabel/Materiali/Tecniche` | ACF label of the active filter |
| action `toggleFilters/togglePill/clearFilters` | Side-panel and filter management |
| action `clearCategoria/clearMateriali/clearTecniche` | Single-filter removal |
| callback `initMap` | Leaflet initialization (run once via `data-wp-init`) |
| callback `updateMarkers` | Marker update on filter change (reactive via `data-wp-watch`) |

**Architecture:**
- Leaflet.js (v1.9.4) is **bundled** directly in `view.js` via npm/webpack — no CDN dependency for the JS
- Leaflet CSS is included in `style-index.css` via `@import url()` (jsDelivr CDN)
- The block uses `viewScriptModule` (not `viewScript`) in `block.json`: required for loading as an ES module and for resolving the `@wordpress/interactivity` import map
- `initMap` sets `ctx.mapInstance` in a `setTimeout` after `invalidateSize()`: this reactive context update automatically retriggers `updateMarkers` via `data-wp-watch`, with no explicit calls
- References that change due to cosmetic interactions (selected marker, side panel, default icon) are kept **outside** `ctx` in a `WeakMap` keyed by `ctx`: writing them to `ctx` would trigger `updateMarkers`'s `data-wp-watch` and thus an unwanted `fitBounds`/`setView` (zoom-out when clicking a single pin after opening a cluster)
- The `posizione_per_mappa` field is read with `get_post_meta()` (not `get_field()`) because ACF Extended with `return_format: leaflet` returns HTML instead of the raw coordinate data

### 5. ACF Field (`ttf-child/acf-field`)

Generic block that displays a single ACF field with label and graphic wrapper. **If the field value is empty, the block emits no markup at all**: no wrapper, no border, no padding — the "render/hide" decision is made server-side and includes the entire surrounding `<div>`.

**Block attributes (configurable from the Site Editor):**

| Attribute | Values | Description |
|---|---|---|
| `fieldKey` | ACF field name | Field to read with `get_field()` |
| `label`    | string         | Bold label before the value (empty = no label) |
| `variant`  | `standard` / `flush` / `top-border` | Graphic wrapper |

**Graphic variants:**

| Variant | Wrapper styles | Typical use |
|---|---|---|
| `standard`   | bottom border + `padding-bottom: 15px` + `margin-bottom: 20px` | `data`, `ubicazione`, `autore`, `tecnica_e_materiali`, `dimensioni`, `edizione`, `trattato_completo` |
| `flush`      | only `padding-bottom: 15px`, no borders                        | `provenienza` (inline rich text preceding `fonti`) |
| `top-border` | top border + `padding-top: 15px`                               | `fonti` (separator before the links block) |

**Editor behavior:** selecting a field from the `SelectControl` auto-populates the label and variant with the preset registered in `index.js` (map of the 9 known fields). The label remains customizable; the preset applies only as long as it matches a registered default — if the user modifies it, switching fields does not overwrite it.

**Rendering:**
- `wp_kses_post( $value )` for all fields (safe both on plain text and WYSIWYG, avoids duplicating text/rich branches)
- `get_block_wrapper_attributes()` to integrate the user className + specific classes `acf-field acf-field--{variant} acf-field--{fieldKey}`
- `sanitize_html_class()` on the fieldKey used as a CSS modifier
